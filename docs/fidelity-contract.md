## Staged compatibility extension

The [accepted source plan](tasks/T174_source_qualification.md), recorded in [T174](tasks/T174_source_qualification.md), prioritizes the current Epic version and native Linux work while preserving Windows/Steam. Build and port work may begin without solving save-format compatibility. Early no-save runs must say progress will not be saved; turning saves off is not permission to bypass source qualification or call the port feature-complete. Other Epic versions come later. Historical Steam observations above remain evidence, not proof for Epic; no source or final gate passes through this scope change.

The [accepted native platform plan](tasks/T175_native_linux_platform.md), recorded in [T175](tasks/T175_native_linux_platform.md), starts with the existing dependency pins and Wayland rather than simultaneous X11 support. Keep the mixer and Windows behavior while adding Linux sound and native launcher fonts/folders/helpers. Graphics, audio and input require separate verification; an isolated software-rendered window does not establish hardware support. No build, runtime or source gate passes through this decision, and broader release hardware remains unmeasured.

The [first port acceptance checklist](tasks/T176_port_acceptance.md), recorded in [T176](tasks/T176_port_acceptance.md), is approved for implementation handoff. Preserve separate Windows/Linux × Steam/Epic results, existing checks, source/cache isolation and truthful no-save behavior. Missing hardware, native Windows or controlled comparison evidence stays BLOCKED/NOT RUN; it does not prevent coding or count as completed support. This approval selects no new reference settings/tolerances, authorizes no new tests, and leaves the later save goal and final gates intact.

## Comparison rules

Each scenario names source identity, rewrite commit, save fixture, language/edition, device, display settings, initial state, timestamped inputs, captured evidence and first divergence. Decoded record identities, discrete game state, flags, inventory, damage, RNG consumption and progression require exact agreement. Numeric rounding, tick alignment, pixel/camera and audio tolerances must be measured and pinned before those gates can pass; none is silently assigned a generous default. Timing uses the identified reference clock, not guessed 60 Hz simulation. Screenshots alone do not prove hidden state.

Layers are tracked separately: decoding, hidden state/rules, timing, rendering, audio, controls, persistence and coverage. Every required record/route remains in the denominator including unknowns. The final finish line is P31 acceptance plus complete P27/P28 ledgers and no unresolved required discrepancy. No percentage or smoke-app result constitutes game equivalence. Enhancements such as extra games, extra voice sources, cloud sync and new rendering effects require a later explicit scope decision.

The agent owns implementation and reproducible measurements. The user owns source edition, physical play/review, devices, save-import priority and release decisions. See `docs/unknowns.md` for the remaining concrete inputs.
