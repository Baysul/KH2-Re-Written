# Bounded private MCP bridge research

[Ghidra MCP pin](https://github.com/bethington/ghidra-mcp/tree/4c5e9429eddc7100be6b4d6bad561d69ab86938f) is Apache-2.0 research tooling, not a product dependency. T012 built its unchanged Java source as `GhidraMCP-7.0.0.jar` against the separately pinned Ghidra 12.1.4 engine on JDK 26.0.2.1. The headless Maven profile excludes Ghidra libraries from the assembly; runtime uses the external distribution's libraries. No extension, mod manager or global MCP configuration was installed.

The source archive SHA-256 is `76dd52d56f8c94de50655303237857f4ae95a7f283507232f64ed643f222f7cf`; the locally built bridge JAR SHA-256 is `821fd573f6162668e7932133dbc791b852166b9f8f5f9339628d95a169b93dbe`. These identify tooling, not the vendor source. Private Maven 3.9.16 matched its [published SHA-512](https://downloads.apache.org/maven/maven-3/3.9.16/binaries/apache-maven-3.9.16-bin.zip.sha512); PGP verification was NOT RUN. Maven's repository, build outputs, Python environment and logs remain external. `uv sync --locked --no-default-groups --python 3.14` installed the pin's locked bridge dependencies, including MCP 1.28.1. No Rust dependency changed. Complete transitive license/installation attestation remains unfinished.

The relevant [pinned importer](https://github.com/bethington/ghidra-mcp/blob/4c5e9429eddc7100be6b4d6bad561d69ab86938f/src/main/java/com/xebyte/core/ProjectProgramProvider.java) uses automatic detection without a language, and raw-binary import with an explicit language. Neither exposes the native PE loader settings required by the observed mixed executable. Do not import KH2FM through this generic endpoint or force a language to bypass that distinction. Prepare a source-bound private project using `Invoke-NativeReader.ps1 -PreservePrivateProject`, the current native oracle and managed inventory, then open that project with `--project <private-gpr> --program <exact-program-name>`. This retains PE mappings and the independently parsed image base; the candidate remains quarantined.

The tested Windows launch uses a Java argument file with the built bridge and complete Ghidra library classpath, `com.xebyte.headless.GhidraMCPHeadlessServer`, a loopback TCP bind and private home/settings/cache/temp directories. This follows the pin's direct headless deployment approach. An initial Utility-only bootstrap failed with a missing class; its logs are preserved. `GHIDRA_MCP_FILE_ROOT` points to the private session directory and `GHIDRA_MCP_ALLOW_SCRIPTS=0`. TCP was qualified; the Unix socket failed because the Windows path was too long. No general transport or host compatibility claim follows.

The server exposes write tools as well as read tools. Our finite MCP stdio client permits only `get_metadata`, `force_decompile`, `disassemble_function` and `read_memory`, verifies their discovered read-only annotations and requires an explicit exact program on every request. It bounds calls, time and saved response size. A read-only annotation is not a security audit. Target execution/debugger, inline scripts, arbitrary imports, renaming and mutation tools were not used for source findings. Program opening can update ownership metadata in the private project; nothing writes into Steam.

Qualification: 48 selected upstream tests passed with zero skips; seven fixture MCP calls produced ten instructions and 64 prefix bytes matching the direct native reader. Recompiling only the authored returned pseudocode with its known initializer/typedef context passed 22 finite comparisons. The response contains literal escaped line endings; normalization was applied only to the authored recompilation, with raw responses preserved. Seven source MCP calls then matched the two previously independently checked getter bodies: five instructions and 32 entry-prefix bytes. Exact target addresses, bytes, values and pseudocode remain private. No target pseudocode was recompiled or executed.

Lifecycle qualification found that `/exit_ghidra` alone stopped TCP/processes but left project marker files. The project reopened without manual marker deletion. Explicit `POST /close_project` before `POST /exit_ghidra` removed the markers; the owned process exited and TCP refused connections. Use this explicit close sequence and verify it for each session. The first failure remains recorded, not relabeled as a clean shutdown. Do not delete user projects or unrelated lock files.

Outside-root authored import, disabled inline-script and missing-program checks all returned semantic errors; this server returned HTTP 200 for them, so callers must inspect the payload. These are three finite boundary checks, not coverage of all 190 registered endpoints. No auto-analysis of the vendor image, active callers, live state, new gameplay rule, supported-build admission or whole-game fidelity is established.
