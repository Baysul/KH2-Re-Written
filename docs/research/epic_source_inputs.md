## 1. Source/profile and package/language boundaries

`validation/src/lib.rs:228-239` requires the executable and six numbered archive pairs under `Image/dt`. E01 was observed under `Image/en`. Neither folder identifies edition, language completeness, storefront authenticity or a supported build. Optional Steam metadata is merely a clue; all scanner outputs remain `quarantined_unqualified`, with dependency and edition unknowns (`validation/src/lib.rs:289-329`). `ProbeSource::bind` requires that exact candidate layout and quarantine value, not an accepted executable-profile registry (`source/data/src/probe_source.rs:142-187`). An exploratory E01 inventory is not interchangeable with that manifest.

There are additional layout consumers beyond validation: the shared `Library` index list (`source/data/src/path_lookup.rs:9-17`), settings language discovery (`source/main/src/test_room/settings_room.rs:8-16`), notice callouts (`source/main/src/test_room.rs:2557-2566`) and item-picture index (`source/main/src/test_room.rs:5694-5695`). Changing only the scanner leaves feature paths broken.

Package precedence is inconsistent today. `Library::find` selects the last matching package and labels patch precedence an inference (`source/data/src/path_lookup.rs:98-124`); launcher config generation selects the **first** (`source/main/src/launcher/install.rs:379-397`); settings inserts all indexes into a name map, so later occurrences replace earlier ones (`source/main/src/test_room/settings_room.rs:78-87`). Evidence must resolve duplicate-name content and native selection before choosing one policy, not simply copy Steam ordinals.

Package folder and internal language paths are separate dimensions. Launcher templates request `menu/us`, `msg/us`, localized face/HUD assets and `.win32.scd` names (`source/main/src/launcher/test_configs.rs:5-79`); the latter are asset names, not proof that decoding requires Windows execution. Settings advertises a language after finding only four core files, although ten menu/message templates and world-command layouts participate (`source/main/src/test_room/settings_room.rs:18-36`, `source/main/src/test_room/settings_room.rs:98-114`). Enemy labels additionally request English journal resources (`source/main/src/test_room/enemy_catalog.rs:134-147`). Thus `en` does not imply internal `en` names, Japanese availability or complete language switching.

## 2. Executable coupling across implemented features

| Coupling class | Owned-code evidence and consequence for E01 |
|---|---|
| **Runtime fixed-location extraction; confirmed failure** | `Sbox::from_executable(exe: &[u8]) -> Result<Self, CipherError>` computes a fixed RVA from compiled constants, maps sections and requires a byte permutation (`source/game/save/src/cipher.rs:42-93`). T172's unchanged Rust call returns `Err(TableNotAPermutation): the cipher table is not a byte permutation`. This does not identify the correct Epic table. |

Therefore, even after archive/profile repairs, the observed Sbox rejection would abort this interactive path before the user chooses Load. Synthetic autoplay uses an in-memory backend and would conceal this blocker. |
| **Compiled input and text tables** | Controller base/field/title mappings (`source/visual/src/controller.rs:119-189`), prompt/icon mapping and widths (`source/visual/src/sprite_player.rs:403-449`), dialogue control lengths/font assumptions (`source/visual/src/dialogue.rs:18-63`) remain compiled baseline interpretations. | **Compiled simulation/interpreter semantics** | Shared physics explicitly names Steam build 15194255 (`source/game/player/src/actor_physics.rs:1-24`); script interpreter and action manager do likewise (`source/game/enemy/src/script.rs:1-20`, `source/game/enemy/src/act.rs:1-17`). Trap argument/result flags are a compiled executable-derived table (`source/game/enemy/src/trap_table.rs:1-30`). Movement, combat, abilities/forms, enemies, scripts, animation/effects and presentation cannot acquire Epic behavioral qualification merely by decoding their data. |

Other implemented consumers fit the same classification: magic combines compiled spell state machines with package `magi`/ATKP records (`source/game/player/src/magic.rs:1-6`); forms retain compiled eligibility/progression logic (`source/game/player/src/forms.rs:1-9`); friend AI mixes decoded personality records with a deliberately unqualified formation distance (`source/game/player/src/party_members.rs:1-15`). Effects retain executable-derived stepping and projection defaults (`source/visual/effect/src/lib.rs:1-9`, `source/visual/effect/src/lib.rs:27-32`); sound bank selection combines compiled request semantics with checked original/replacement reads (`source/visual/src/sound.rs:1-30`). Event playback consumes decoded scripts rather than loading a PE table (`source/game/event/src/lib.rs:1-7`). These are feature-specific compatibility checks, not reasons to recover every Epic executable routine before implementation.

The bounded KH2 source search found the save cipher as the concrete runtime installed-PE table extractor; it did **not** find a general loader that replaces compiled gameplay/UI tables by storefront. Address comments are provenance, not runtime PE reads. Conversely, package-driven battle/object/motion data are not fixed-RVA extraction: for example enemy inspection reads `00objentry.bin` through `Library` (`source/main/src/test_room/enemy_catalog.rs:134-138`). These distinctions prevent both undercounting compatibility risks and inventing executable dependencies.

## 3. Decoding, session revalidation and cache identity

T172 establishes 46,076 structurally checked entries, **30 original and 8 HD samples** decoded by mirrored Python, not Rust. It does not establish exhaustive decode, pixels, motion, audio, renderer behavior or Steam/Epic equality. The transform's pinned provenance is OpenKH commit `7a3b945c538d32c6a285128c98aefba093f52ceb` (`source/data/src/original_payload.rs:1-4`); that attribution is not E01 compatibility evidence. No new external-library API or recommendation is asserted here.

Every gameplay session must retain selected-source checking: schema 2 rehashes executable/indexes, checks package metadata, and verifies accessed package chunks; schema 1 falls back to full verification (`source/data/src/probe_source.rs:208-285`). Launcher `quick_match` only compares manifest consistency and metadata; it is not that admission (`source/main/src/launcher/install.rs:215-236`). Title and test-room entry invoke session verification (`source/main/src/title.rs:810-814`, `source/main/src/test_room.rs:2625-2631`). Preserve these boundaries with an explicit qualified profile rather than treating quarantine as support.

Current content identity includes relative names, lengths and file digests, excluding host paths/timestamps (`validation/src/lib.rs:213-226`). Generated configs are reused by that identity alone (`source/main/src/launcher/install.rs:319-322`, `source/main/src/launcher/install.rs:358-396`). The 32-chunk memory cache is per reader and digest-checked on initial load (`source/data/src/probe_source.rs:31-43`, `source/data/src/probe_source.rs:79-102`), not an implemented persistent decoded-cache qualification scheme. Recommendation: future derived artifacts bind source identity **and** profile/language/precedence/decoder revision; never relabel Steam selections as Epic or let cached artifacts replace session checks.
